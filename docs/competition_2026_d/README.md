# 2026 D题陆空协同系统：分工总览

## 目标

本目录是 D 题四个工作组的协作入口。所有成员按各自计划实施，但跨模块数据必须遵守唯一协议文档 `communication_protocol.md`，不得在各模块内另行定义同名字段、单位、状态值或校验方式。

## 已确认的官方答疑

- 允许在小车平台增加 AprilTag、二维码或彩色方向标志。
- A 点以小车车头到达 A 点标线为准，不以车尾或车体中心为准。
- 伴飞期间无人机允许降低高度。
- 当前开发阶段采用一个位于降落圆盘中心的 AprilTag 作为主定位目标；双圆环继续保留。若实体Tag遮挡十字交点，当前阶段以Tag为主，不假定十字仍可作为完整近地备份；正式赛前再确认中心贴法或恢复十字。

## 系统数据流

```text
Cyber Camera --VS1观测--> 无人机Pi/RDK --现有串口--> STM32飞控
                                  ^
                                  |
                    /dev/bt_serial @115200
                                  |
                                  v
                                小车

无人机/小车 --统一遥测协议--> 地面站（只显示和记录）
```

Pi/RDK 是唯一高层飞行决策者。Cyber Camera 只提供观测，小车只提供启动与运动状态，地面站不进入控制闭环，STM32保留实时控制和底层安全。

## 共同里程碑

1. 冻结通信协议 v1、坐标系、单位、状态枚举和测试向量。
2. 四组分别完成单板最小验证。
3. Cyber Camera → 无人机视觉链路联调。
4. 小车 ↔ 无人机蓝牙启动、状态与触地确认联调。
5. 地面站监听同一协议并完成离线显示。
6. 板载拆桨联合检查。
7. 按静态视觉、移动伴飞、投放、动态降落顺序实飞。

## 协作规则

- 协议唯一来源：`communication_protocol.md`。
- 协议改动必须先更新版本和测试向量，再同步四组。
- 所有日志携带同一 `session_id`、本地单调时间和消息序号。
- 四组可以独立开发，但联调前必须通过协议测试向量。
- 地面站或蓝牙显示链路故障不得阻塞飞行主循环。
- 安全关键行为以无人机控制计划为准，不允许由通信异常直接覆盖。
