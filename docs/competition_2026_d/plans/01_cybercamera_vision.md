# 分工计划01：Cyber Camera视觉检测

## 目标

使用圆盘中心的单个 AprilTag 作为主定位目标，同时保留正式30/50cm同心圆环与十字图案作为兼容特征、交叉校验和近地备份，输出稳定、新鲜、可校验的平台观测，为伴飞、投放和动态降落提供统一输入。

## 官方答疑与当前简化决策

- 官方允许在小车平台增加 AprilTag、二维码或彩色方向标志。
- 当前只使用一个 AprilTag，贴在降落圆盘中心，不先引入多Tag布局和Tag间偏移换算。若贴纸遮挡十字交点，当前开发阶段以Tag为主，不把被遮挡的十字作为可用备份；正式赛前再确认是否保留中心贴法。
- 无人机固定机头、不主动偏航；小车转向只会使Tag在画面内旋转，不会改变Tag中心所表示的降落中心。
- `angle_cdeg`保留输出Tag平面航向，用于诊断、转弯识别和后续速度前馈，不用于命令无人机跟随旋转。
- 二维码暂不进入实时视觉伺服主链路；彩色方向标志仅作为后续搜索/丢失恢复候选。

## 输入与输出

- 输入：Cyber Camera外接CSI0下视摄像头画面；板载CSI2摄像头保持关闭，不作为D题输入。
- 输出：`../communication_protocol.md` 定义的VS1帧。
- 不输出：飞行速度、投放命令、降落状态决策。

## 工作内容

1. 确认采集后端、分辨率、视场角、曝光和实际帧率。
2. 增加中心AprilTag检测，输出Tag中心、平均边长、平面航向、ID校验结果和质量；正式任务只接受配置中指定的单一Tag ID。
3. 检测双圆比例、同心性、椭圆透视和中心十字；AprilTag正常时以Tag中心为主。Tag失效后远距以外圆为主、中近距以内圆为主；只有十字交点未被Tag遮挡且通过完整性校验时，近地才允许切换到十字，局部圆弧只作为受连续性约束的辅助观测。
4. AprilTag、外圆、内圆和十字候选并行评分；来源切换连续确认至少3帧。候选中心冲突、圆弧覆盖不足或只有十字单臂时输出 `AMBIGUOUS`/无效，不进行单帧硬切。
5. 输出中心、尺度、角度、质量、特征有效flags、`stream_id`、序号、采集时间和CRC。
6. 提供显式 `blue_square` 调试模式，用25 cm蓝色方形验证水平控制；正式任务默认拒绝该替代目标。
7. 完成串口断开、画面遮挡和旧观测处理。
8. 本地保存早期调试视频/关键帧和检测耗时，不经UART传图。

## AprilTag实现状态（2026-07-29）

- Cyber Camera使用OpenCV 4.10.0的 `DICT_APRILTAG_36H11` 灰度检测，当前配置为ID 0；打印总尺寸150 mm、有效Tag尺寸120 mm。
- `APRILTAG_VALID` 使用VS1 flags bit 7；指定ID必须唯一，错误ID、多Tag或来源标志冲突输出无效/`AMBIGUOUS`。
- 当前测试标志保持“25 cm蓝色方形外框＋中心AprilTag”。融合模式先由ID 0 Tag确认身份，随后优先用蓝框高频定位；输出 `APRILTAG_VALID|COLOR_SHAPE_TRACKED`（bit 9），蓝框不能独立建立身份。蓝色失效时回退Tag直接解码/短时光流，视觉全部失效时由T265保持。
- RDK对颜色融合和Tag光流均限速0.12 m/s，Tag直接解码允许最高0.18 m/s；三种模式继续共用加速度和jerk限制。专项静态测试已关闭0.5 m软围栏，仅保留0.8 m紧急半径；正式伴飞不能使用固定接管点半径阻止持续跟车。
- 融合闭环实飞1确认X方向正确、Y方向符号错误；现已恢复“画面上方为+Y”。融合闭环实飞2在1.5 m将像素误差从约227 px降至最小31 px，XY方向和收敛均已确认。
- 当前采用更简单的持续追踪流程：1.5 m确认正确Tag后立即启用XY视觉伺服，下降到1.0 m期间持续追踪，到达1.0 m后继续居中，不释放或重新接管。运行时关闭以接管点为圆心的0.5 m软围栏；专项测试暂保留0.8 m紧急半径、速度/加速度限制和视觉丢失原地保持。最终伴飞改用场地/赛道边界，不能使用固定接管点半径阻止持续跟车。
- 几何质量由像素边长、画面边距、四边一致性和四边形形状四项的最低分决定，默认要求平均边长至少18 px、闭环质量至少55。
- RDK的 `apriltag` 与 `blue_square` 来源互斥，切换配置后必须重启进程；AprilTag不允许进入 `PARTIAL_COARSE`。
- 起飞门禁要求指定Tag连续3帧有效；视觉接管后使用0.3秒新鲜度门限，短时由颜色/Tag光流续跟，完全失效后交回T265保持。专项测试使用0.8 m紧急半径。
- 首次部署必须先更新RDK再更新Cyber Camera，并先做无桨双向通信与真实打印Tag静态测试。

## AprilTag＋蓝框融合实飞结果（2026-07-29）

- 1.5 m只观察悬停15秒：152帧序号连续，观测频率10.09 Hz，149帧有效（98.0%）；颜色主定位78.9%、Tag光流15.8%、Tag直接识别3.3%、完全丢失2.0%。最长完全丢失约0.25秒，平均接收年龄17.3 ms。
- 融合闭环实飞1：下降到1.0 m前未居中，目标因透视放大部分出画；重新捕获后X方向正确，Y方向错误并将目标推向画面上边缘。已依据实飞恢复 `error_y=240-cy`，即画面上方为无人机 `+Y`。
- 融合闭环实飞2：在1.5 m将中心误差从约227 px降至最小31 px，降幅约86%，XY方向和收敛均确认正确。任务以20秒专项测试上限退出；未完全居中主要因为旧0.5 m软围栏限制继续追踪，不是检测或方向失败。
- 已实现持续追踪状态机：1.5 m确认正确Tag后立即启用XY视觉伺服，下降到1.0 m期间不释放接管，到达1.0 m后继续居中。该版本已通过单元测试并部署RDK，但“边追踪边下降”仍待下一次实飞验证。

## T-018 蓝色方块1.5米实飞结果（2026-07-29）

- 航线为 `1.5m → 0.15m → DESCEND`，视觉只采数，不向飞控输出水平速度。
- Cyber Camera外接CSI在实飞期间约37.7 FPS；VS1共12428帧，CRC错误0、序号缺口0。
- 1.4m以上稳定段约16.3秒，蓝色方块识别率约39.9%，检测中心平均约 `(509,443)`，平均像素边长约105px。
- 227个有效检测中约225帧的方块下边缘已超出画面。每秒调试图也显示目标长期处在画面下边缘，因此本次识别率下降主要由初始相对位置和部分出画造成，不是1.5米距离下目标过小。
- 当前蓝色方块检测器对完整轮廓稳定，但边缘截断后会间歇输出 `NO TARGET`。进入水平闭环前，需要增加“蓝色区域接触边框”的粗定位分支：置 `PARTIAL | SURROGATE_SQUARE`，降低质量，只用于低速把目标拉回视野；完整轮廓连续确认后再切回精定位。

实飞调试图片记录参数：

```bash
--debug-record on \
--debug-record-dir /home/pi/FJJ/cybercam_d/debug_frames \
--debug-record-interval 1
```

正式运行或不需要图片时使用 `--debug-record off`。记录逻辑复用长驻CSI数据流，不允许每秒调用 `capture_once.py` 重新打开摄像头。

## 阶段

- C0：采集链路与正式图案尺寸确认。
- C1：静态中心、边缘、遮挡和黑线干扰。
- C1.5：25 cm蓝色方形静态控制测试，依次完成拆桨方向检查、单轴低速和二维居中；不开放视觉高度控制。
- C2：中心AprilTag静态检测、人工平移/旋转、遮挡和指定ID拒绝测试。
- C2.5：真实小车直线、加减速和弯道检测，确认小车转向时Tag中心连续且航向变化正确。
- C2.6：相机从1.5m逐级贴近到起落架接触高度，测出AprilTag/外圆丢失高度和最低可靠视觉高度。
- C3：达到上机门槛后冻结VS1 v1。
- C4：上机首次只采数，确认振动、roll/pitch和桨影影响。

## 验收

- 实际1.5m距离能稳定识别正式平台。
- 小车原地旋转和弯道行驶时，中心AprilTag的定位中心不得随Tag朝向产生系统性偏移。
- 只接受配置的Tag ID；相邻或场地中的其他Tag不得进入控制闭环。
- 从外圆出画到最低可靠高度期间，内圆/十字模式能连续给出中心及明确质量标志；再低时必须输出 `TOO_CLOSE`，不得伪造有效目标。
- 停止相机后不持续输出旧有效目标。
- 循迹线/边框不形成持续误检。
- 蓝色细线、长方形和小面积蓝色噪声不能通过替代目标筛选；正式任务不能使用 `SURROGATE_SQUARE`。
- 正式特征来源切换时中心无控制级跳变，新来源连续3帧确认后才接管。
- 有效观测频率和延迟足以进入低速伴飞实飞。
- 输出通过统一VS1测试向量。
