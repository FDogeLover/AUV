# 光流 vs T265 速度相关性分析脚本 — 设计

## 背景

已知问题（见项目 `.claude/CLAUDE.md` "已知未解决问题"第2条）：手持晃动测试中，光流融合速度 `of1_dx/dy` 与 T265 速度相比，交叉轴相关性（T265_X vs 光流_Y）明显强于同轴相关性，暗示光流安装朝向可能与机体差了约90°。此前只做过一次约4秒的手持测试，样本量不足，需要一个可复用的离线分析工具，用已采集的飞行日志（`flight_data.jsonl`）定量验证这个假设。

`ubuntu-pi` 上已有一份真实日志：`/home/sunrise/Desktop/FJJ/basic/flight_data.jsonl`（387行，覆盖多个飞行状态），可直接用于本次分析，无需重新采集。

## 目标

写一个离线诊断脚本，读取 `flight_data.jsonl`，计算 T265 速度与光流融合速度之间的同轴/交叉轴相关系数，并做小范围时延扫描，输出结论性文字提示，帮助判断坐标系是否存在约90°旋转。

## 非目标

- 不做图形绘制
- 不修改飞控固件或上位机代码
- 不做自动坐标系修正

## 输入

脚本命令行参数：`flight_data.jsonl` 文件路径（默认当前目录下同名文件）。

日志每行是一个 JSON 对象，相关字段：
```json
{"t265_vel": [vx_m_s, vy_m_s], "of1_vel_cms": [dx_cm_s, dy_cm_s]}
```
没有这两个字段的行（如 `{"event": "task_start"}`）直接跳过。

## 处理逻辑

1. 逐行解析，提取 `(t265_vx, t265_vy, of_dx, of_dy)` 序列，跳过缺字段的行。
2. 过滤噪声：只保留 `|t265_vx| 或 |t265_vy| 或 |of_dx| 或 |of_dy|` 超过阈值（默认 `t265` 阈值 0.02 m/s，`of` 阈值 2 cm/s）的样本，避免静止时的传感器噪声主导相关系数。可通过命令行参数覆盖阈值。
3. 纯 stdlib 实现 Pearson 相关系数函数（不引入 numpy 依赖）。
4. 时延扫描：对样本序列做 -5 ~ +5 个采样点的整数位移（shift），每个位移下重新计算：
   - 同轴：corr(t265_vx, of_dx)，corr(t265_vy, of_dy) → 取绝对值均值作为该位移的"同轴强度"
   - 交叉轴：corr(t265_vx, of_dy)，corr(t265_vy, of_dx) → 取绝对值均值作为该位移的"交叉轴强度"
5. 输出一张文本表格：每行是一个位移值 + 同轴强度 + 交叉轴强度。
6. 结论文字：找到全局同轴强度最大值和交叉轴强度最大值，比较两者，输出一句话结论（例如"交叉轴相关性峰值 0.71 > 同轴相关性峰值 0.34，支持约90°旋转假设"）。同时报告有效样本数量，样本过少（如 <30）时给出"样本量不足，结论仅供参考"的提示。

## 输出

纯终端打印，格式示例：
```
有效样本数: 214 (过滤阈值: t265>0.02m/s, of>2cm/s)

位移(样本) | 同轴强度 | 交叉轴强度
-5         | 0.21     | 0.55
...
 0         | 0.34     | 0.71
...
+5         | 0.18     | 0.40

结论: 交叉轴相关性峰值 0.71 (位移0) > 同轴相关性峰值 0.34 (位移-2)，支持约90°旋转假设。
```

## 文件位置

`drone_control/tools/analyze_of_t265_correlation.py`（新建 `tools/` 目录）。纯 Python 标准库实现，无第三方依赖，可在本机或 `ubuntu-pi` 上直接运行。

## 测试

用真实日志 `flight_data.jsonl`（需从 `ubuntu-pi` 拷贝到本地或直接在 pi 上跑）跑一遍，确认输出合理（不崩溃、样本数非零、表格数值在 [-1,1] 范围内）。不写自动化单元测试——这是一次性诊断工具，正确性以真实数据跑通为准。
