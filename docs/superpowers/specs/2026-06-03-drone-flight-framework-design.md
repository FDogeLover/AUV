# 无人机基本飞行控制框架完善 — 设计方案

- 日期：2026-06-03
- 范围：`ANO_LX_FC_倾角保护版`（飞控固件）+ `drone_control`（树莓派上位机）
- 不涉及：K230 视觉部分

## 1. 背景与目标

在现有"高层规划在 Pi、实时闭环在飞控/匿名 IMU"的系统上，完善基本飞行控制框架，达成三个目标：

1. **自由控制飞行高度**：飞行中可下发任意目标高度并平滑过渡。
2. **T265 定位更准**：先修正一键起飞时往固定方向（世界系 -x/-y）的漂移，再提升定位质量。
3. **基本飞行控制框架更完善**：恢复关键安全链路、集中参数、增强状态机健壮性。

## 2. 约束与前提（决定方案形态）

- **无台架，但可试飞**；可用**匿名 IMU 上位机显示/接收数据**——这是主要观测与诊断手段。
- **水平自稳是匿名 IMU 内的闭源函数**，唯一可控接口是**喂给它的 vx/vy**（替代光流）。自稳算法本身不可改。
- **高度环是项目自有的 `height_set`**（`Mycode/my_protocol.c`，输出 vel_z 经 `rt_tar`），完全可控。
- **偏航锁定为 0**（`yaw_pid` 目标 0）。本方案**保持锁偏航**；自由偏航会使 T265 世界系速度与机体系不一致、破坏速度帧约定，当前不需要（YAGNI）。
- **C 源文件为 GB2312 编码**（Keil 限制）：改动 `.c/.h` 一律用 `sed`，禁止 Read/Edit 工具链；Python 文件 UTF-8 正常编辑。

## 3. 总体数据流（明确两个 T265 功能的上下层关系）

```
功能1 速度自稳（地基）：
  T265 vx/vy ─AA01─> 飞控 pi_receive ─flex 0xF1─> 光流/IMU口 ─> 匿名自稳(黑盒)

功能2 定位飞行（骑在功能1之上）：
  T265 位置 vs 目标 ─x/y PID─> 期望速度 ─AA02 com_x/com_y─> rt_tar.vel_x/y ─> 匿名自稳

高度（自有闭环）：
  目标高度 com_z ─AA02─> height_set(激光高度 of_alt_cm) ─> rt_tar.vel_z

下行遥测：
  飞控 pi_send() ─AA..FF 19字节─> Pi listen_fc ─> 激光高度融合 + 2s超时急停 + 日志
```

**关键认知**：功能2 的 PID 输出最终也走速度通道、仍由匿名自稳执行；因此**功能1 的 vx/vy 约定必须先正确**，否则功能2 再准也被带偏。这决定了实现顺序 ①→②→③。

## 4. 工作块 ①：速度自稳约定对齐（修起飞漂移）— 地基

### 4.1 问题定性
起飞往固定方向漂移，且唯一可改处是喂入的 vx/vy，故根因锁定在 **T265→光流 vx/vy 的符号 / 轴向 / 量纲是否匹配匿名光流约定**，候选（按概率）：
1. 速度符号反 → 正反馈 → 持续单向漂（最可能）
2. 静止零偏 → 自稳当真实运动去补偿
3. 轴向/坐标系不匹配（起飞时偏航≈0，影响小，非主因）

### 4.2 诊断方法（无台架，用匿名上位机）
1. 通电、T265 校准后，飞机不解锁，在匿名上位机观察喂入自稳的速度值。
2. 手持飞机分别朝物理 +前 / +右 平移，记录显示速度的符号与轴。
3. 对照匿名光流的正方向约定，列出"物理移动方向 → 应得速度符号"对照表，定出正确映射。
4. 静止放置，记录速度零偏均值。

### 4.3 实现（改动集中在 Python，编辑安全）
- 在 `drone_control` 增加**速度标定层**（位于 `t265.py` 输出或 `Lprotocol._send_t265_loop`）：
  - 可配置 `VEL_SIGN_X / VEL_SIGN_Y`（±1）与可选轴交换 `VEL_SWAP_XY`。
  - 可配置静止零偏 `VEL_BIAS_X / VEL_BIAS_Y`，发送前扣除。
- **降低喂给自稳的滞后**：当前位置与速度共用 `alpha=0.15`。将**速度滤波系数独立**（如 `alpha_vel=0.3~0.5`，更跟手），位置保留较重滤波。两者解耦，单独可调。
- 全部参数进入集中配置（见 §7）。

### 4.4 验证（Go/No-Go）
- 匿名上位机：手持移动时速度符号与对照表一致。
- 试飞：一键起飞后悬停**不再单向漂移**（可被遥控拉回、松手不跑）。未通过则不进入 ②。

## 5. 工作块 ②：自由控制飞行高度（飞控端闭环）

### 5.1 目标高度斜坡平滑（Pi 端）
- `com_z` 语义为"目标高度(cm)"，飞控 `height_set` 对其做 PID。为避免任意改高时速度跳变：
  - 在 `Mission_GPT` 维护 `com_z_cmd`，每周期以可配置爬升/下降速率 `CLIMB_RATE_CMPS` 朝航点目标高度逼近，再写入 `se_fc[5]`。
  - 飞控侧无需改动即获得平滑设定点。

### 5.2 `height_set` 完善（飞控端，sed 编辑 GB2312）
- 启用项目内已存在的注释版增强逻辑：
  - **倾斜补偿**：用 `fc_att` 的 roll/pit 把激光斜距换算为垂直高度，避免水平移动时高度波动。
  - **积分分离 + 真积分累积**：误差过大清积分防饱和。
- 保留输出限幅（当前 ±30），限幅值纳入可调常量并写明位置。

### 5.3 起飞改为基于激光高度判定（Pi 端）
- 现状 `takeoff()`：置 `se_fc[2]=1` 后 `sleep(1)` 即转 NAVIGATE（开环）。
- 改为：触发任务后**轮询下行激光高度**，达到目标起飞高度阈值（或高度稳定）后再转 NAVIGATE；带超时与失败保护。
- 依赖下行帧（见 ③ 恢复 `pi_send()`）。

### 5.4 验证
- 飞行中下发不同目标高度，匿名上位机 + `flight_data.jsonl` 观察高度平滑过渡、无跳变、稳态误差收敛。

## 6. 工作块 ③：框架完善 + 安全

### 6.1 恢复下行帧 `pi_send()`（飞控端，sed）
- `Ano_Scheduler.c` Loop_50Hz 中 `pi_send();` 当前被注释，导致 Pi 端**激光高度融合、2s 超时急停、到达 Z 判断、日志**全部失效。
- 取消注释恢复下行；用 Pi 日志确认 19 字节帧稳定到达、`fc_last_rx_time` 持续更新。

### 6.2 参数集中化（见 §7）
将散落在 `Mission_GPT`、`my_protocol.c`、`User_Task.c` 的参数收敛到明确位置。

### 6.3 状态机健壮性（Pi 端 `Mission_GPT`）
- 起飞改为高度判定（§5.3）。
- 到达判断、单航点超时、降落时序保持现有逻辑并复核；急停（飞控超时 / T265 停止）路径保留。
- 降落阶段确保高度平滑下降而非直接置 0。

### 6.4 调参数据记录规范化
- 现有 `flight_data.jsonl` 增补字段：喂给飞控的 vx/vy、激光高度、追踪置信度、com_z_cmd，便于事后调参分析。

## 7. 参数集中化设计

- **Python 侧**：新增 `drone_control/Lcode/config.py`，集中：
  - 速度标定：`VEL_SIGN_X/Y`、`VEL_SWAP_XY`、`VEL_BIAS_X/Y`、`alpha_vel`、位置 `alpha_pos`
  - 控制：`VEL_SCALE`、XY/Z 到达阈值、确认次数、超时、`CLIMB_RATE_CMPS`、飞行高度
  - 频率：速度帧/指令帧/地面站发送频率
  - 现有模块改为从 `config` 读取，消除魔法数字。
- **C 侧**（GB2312，sed）：高度/位置 PID 增益与限幅集中在 `my_protocol.c` 的 `PID_init()` 与 `height_set` 限幅处，加统一注释标记块；不强行跨文件重构，降低编码风险。

## 8. 验证与测试策略（无台架，增量试飞）

每块独立 Go/No-Go，未过不进入下一块：
- **①**：匿名上位机符号对照一致 + 悬停不漂 → 进入 ②
- **②**：高度平滑过渡 + 稳态收敛 → 进入 ③
- **③**：下行帧稳定到达 + 超时急停可触发（断开飞控验证）+ 配置正确加载
- 全程依赖：匿名 IMU 上位机遥测 + `flight_data.jsonl` 日志。
- 试飞安全：小空间、低高度、遥控随时可急停（CH_8 / 倾角保护）。

## 9. 明确不做（YAGNI）

- K230 视觉检测相关逻辑。
- 自由偏航控制（保持锁偏航）。
- 位置+速度统一估计器/互补滤波的大重构。
- 跨 MCU 平台（仅针对当前 STM32F407 + 匿名 IMU 组合）。

## 10. 风险

- **自稳约定为黑盒**：vx/vy 正确映射只能经验标定，依赖匿名上位机观测与试飞验证。
- **GB2312 编码**：C 改动必须 sed，避免 Read/Edit 破坏中文注释。
- **试飞风险**：每步小步验证，保留遥控急停与倾角保护。
- **下行帧恢复**后需确认不影响原 50Hz 任务时序与匿名协议交换。
