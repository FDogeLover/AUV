## R1 — 纯航线覆盖（最简可飞）

**目标：** 从起降点起飞 → S型飞完所有绿格（每格闪激光笔2次）→ 返航降落

| 模块 | 内容 | 测试策略 |
|------|------|---------|
| `grid_map.py` | 28个网格到 (x,y) 坐标的映射，标注绿/灰属性 | 纯逻辑，本地 `-m fast` |
| `coverage_planner.py` | 生成S型覆盖路径，起点21号格，跳过灰格 | 纯逻辑，本地 `-m fast` |
| `laser_spray.py` | 包装 gpio_led，到达网格后闪1-3次 | 纯逻辑，本地 `-m fast` |
| `plant_config.json` | 场地配置（巡航高度150cm，网格坐标） | — |
| `main.py` | 添加 `--dry-plan` 预览航线 / `--spray` 执行喷洒 | — |
| `Mission_GPT.py` | 极小改动：`load_waypoints()` 改为从 coverage_planner 加载 | 板上 `-m smoke` |
| `hardware_preflight.py` | 从 competition_2026 复制（不改） | 板上运行 |

### Mission_GPT.py 的修改方式

只改两处：
1. `load_waypoints()` — 检测到 `plant_config.json` 存在时，调用 coverage_planner 生成航点替代 `router.txt`
2. 在 `NAVIGATE` 到达每个航点时，调用 `laser_spray.spray()` 触发激光笔闪烁

**不动**状态机结构、降落逻辑、安全保护等已稳定的部分。

### 测试结果

```
# 本地 (纯逻辑, <5s)
pytest -m fast -v

# 板上 (核心兜底, <30s)
pytest -m smoke -v
python hardware_preflight.py
```

## R4 — 动态障碍（发挥①）

## 关键技术决策

### 1. Mission_GPT 的修改原则

**最小侵入** — 只修改 `load_waypoints()` 和航点到达回调，不动状态机主体。状态图保持不变：
```
IDLE → TAKEOFF → NAVIGATE → DESCEND → LAND → END
                      ↕                      
                 （植保回调注入）
```

### 2. 测试分层

| Marker | 运行位置 | 内容 | 预期耗时 |
|--------|---------|------|---------|
| `-m "fast"` | **本地** | 纯逻辑：grid_map, coverage_planner, laser_spray, config 解析 | < 5s |
| `-m "smoke"` | **板上** | 硬件相关：带 FakeVideoSource 的集成测试、协议测试 | < 30s |
| 无标记 | 本地/CI | 全量测试 | < 2min |

### 3. 配置驱动设计

`plant_config.json` 控制所有场地参数，包括：
- 网格坐标（便于现场调整）
- 每个网格的绿/灰属性（发挥①只需改这里）
- 巡航高度、停留时长等

**不改代码即可适应场地变化。**
