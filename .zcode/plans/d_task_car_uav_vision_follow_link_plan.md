# 计划：D题小车—无人机通信与视觉伴飞前馈

## 问题描述与目标

小车硬件已经可运行，下一阶段需要验证无人机能否通过 AprilTag/颜色融合视觉持续跟随移动小车。仓库已经具备 DCP v1 二进制协议、`/dev/bt_serial` 115200 双向链路、CRC、ACK、重发和 `CAR_STATE` 帧，但目前：

- 蓝牙链路尚未接入视觉伺服实飞入口；
- `CAR_STATE(speed_mm_s, heading_cdeg)` 尚未转换为无人机 T265 世界坐标速度前馈；
- 没有独立于飞控/解锁的车机双向联调工具；
- 没有对小车状态的新鲜度、来源、序号、速度范围和方向约定做飞行侧门禁。

目标分两阶段完成：

1. 不带桨完成车机双向通信验证：无人机周期发送 `UAV_READY/HEARTBEAT`，接收并显示 `CAR_STATE/CAR_START`，记录 TX/RX、CRC/拒绝、ACK/重发和数据年龄。
2. 在显式参数开启时，把新鲜且合法的小车速度作为视觉伺服前馈；视觉负责相对位置纠偏。
3. 把已测量的 A/B/圆弧/C/D 路径构造成按弧长参数化的参考轨迹。视觉丢失但 `CAR_STATE` 仍新鲜时，根据小车广播的累计路径进度 `track_s_mm` 继续进行地图伴飞，而不是立即悬停。

第一轮仍使用 RDK 本地物理按键起飞，蓝牙消息不直接解锁。

本仓库只实现无人机侧和共享协议/联调说明，不创建或修改小车工程代码。

## 方案选择

| 方案 | 优点 | 缺点/风险 |
|---|---|---|
| A. 只做串口收发测试，不接飞行 | 最快、风险最低 | 无法验证移动目标前馈，后续仍需再次改造 |
| B. 一次性让 `CAR_START` 远程解锁并接入速度前馈 | 最接近最终任务流程 | 通信方向和车速字段尚未真机验证，远程解锁风险过高 |
| C. 分阶段：先双向台架验证，再接入“路径进度主跟随 + 视觉纠偏”，保留本地按键 | 视觉短时中断仍可伴飞，同时隔离解锁风险 | 要求车机两端统一路径进度定义和地图坐标 |

**选择方案 C。** 当前首要目标是验证视觉能否跟随小车，不应把“无线远程解锁”与“首次速度前馈”两个高风险变量同时引入。

## 协议约定

- 继续使用 DCP v1，不另建文本协议。
- 物理链路：无人机 `/dev/bt_serial`，115200 8N1。
- 小车以 10~20 Hz 发送 `CAR_STATE`：
  - `segment:u8`
  - `track_s_mm:u16`
  - `speed_mm_s:i16`
  - `heading_cdeg:i16`
  - `flags:u16`
- `heading_cdeg` 明确定义为无人机 T265 世界 XY 坐标系中的航向：`0°=+X`、`+90°=+Y`、逆时针为正。若小车端坐标系不同，由无人机配置 `heading_offset_deg` 和 `heading_sign` 做一次性转换。
- `track_s_mm` 定义为从 A 点起、沿赛道中心线递增的本圈累计弧长，A 点为 0；到达终点 A 后允许回到 0 开始下一圈。它不是当前分段内距离。车机两端必须使用同一份路径版本和累计距离表。
- 无人机收到状态后按接收年龄做短时前推：`s_now = track_s + speed * rx_age`，但前推时间不得超过状态新鲜度门限。
- `CAR_STATE.flags` 至少定义：
  - bit0 `SPEED_VALID`
  - bit1 `HEADING_VALID`
  - bit2 `TRACKING_VALID`
  - bit3 `RUNNING`
  - bit4 `STOPPED`
- 初次直线测试要求小车明确发送有效速度和航向；无效 flags、超龄、非法来源、过大速度均不得进入前馈。

## 视觉与路径的控制权设计

视觉控制器和航点控制器不得各自直接向飞控发送速度，也不采用“谁最后写入谁生效”。系统只保留一个最终水平速度输出端，按以下顺序工作：

1. **路径参考层**
   - 根据新鲜 `CAR_STATE.track_s_mm` 得到小车在统一中心线上的预测位置 `p_path`、切线方向和基础速度 `v_path`。
   - 路径使用连续累计弧长 `s`，离散航点只用于构造插值曲线，不作为必须逐点到达的任务索引。
2. **视觉创新层**
   - AprilTag/颜色融合只输出“小车真实相对位置与路径预测之间的偏差” `innovation_visual`。
   - 视觉不单独生成另一套完整航点速度，不改变路径进度。
3. **目标融合层**
   - `p_target = p_path + alpha * clamp(innovation_visual)`。
   - `alpha` 按视觉连续确认、质量和年龄平滑变化，而不是 0/1 瞬时切换。
   - 视觉丢失时 `alpha` 在有限时间内平滑衰减到 0；视觉恢复时连续多帧确认后再平滑上升。
4. **唯一控制器**
   - 统一控制器根据 `p_target`、`v_path`、无人机 T265 位置/速度计算一次速度命令。
   - 最后统一执行总限速、加速度、jerk、地理围栏和高度门禁。
   - 任意时刻只有该控制器可以写入飞控水平速度。

### 航点越过与跳点

- 小车实时路径进度 `s_car` 是切点依据，不以视觉控制结束时的旧 waypoint index 为依据。
- 控制器选择“累计弧长严格大于 `s_car + lookahead` 的第一个路径点”作为内部前视点。
- 如果小车已经越过一个或多个离散点，所有累计弧长小于当前有效进度的点一次性跳过，不要求无人机倒飞补点。
- 当前进度在同一圈内只能单调前进；允许小范围通信抖动，但拒绝无合法 A 点回绕依据的大幅倒退。
- A 点回绕由当前 segment、上一帧接近路线末端以及新值接近 0 三个条件共同确认，不能仅凭 `track_s_mm` 变小判断新一圈。
- 如果无人机与当前小车参考位置相差超过安全追赶距离，不继续提高速度硬追，转入限速 `INTERCEPT/SEARCH_TARGET`，重新建立视觉或缩小位置差后再进入伴飞。

### 模式与切换

- `PATH_ONLY`：路径/通信有效，视觉不可用，`alpha=0`。
- `VISION_PATH`：路径和视觉都有效，`alpha` 平滑处于 `(0, 1]`。
- `VISION_ONLY_DEGRADED`：路径通信短时失效但视觉连续有效，仅允许短时间低速相对跟随。
- `PREDICT_HOLD`：视觉和通信同时失效，短时延续最后可信运动，随后减速至 T265 定点。
- 伴飞阶段“目标已居中”不代表视觉任务结束；关闭静态测试使用的 `centered_hold_complete` 自动退出，视觉校正持续到任务状态机明确进入抛投、下降或返航。
- 模式切换时清理不适用的确认窗口/微分历史，视觉修正本身不使用积分项；最终命令始终经过同一速度整形器，防止恢复视觉时跳变。

## 风险点

- **安全风险：旧车速或旧路径进度持续驱动。** 使用接收端单调时间判断新鲜度；超过约 0.25 s 立即停止路径推进，不使用发送端时钟判断。
- **安全风险：方向约定反向。** 带桨前先在台架打印 `(vx, vy)`；首飞小车仅沿已验证的单一方向低速运动。
- **安全风险：蓝牙帧直接触发解锁。** 本轮明确禁止，保留本地物理按键。
- **视觉丢失。** `CAR_STATE` 新鲜且路径版本一致时允许进入 `PATH_ONLY`，但设置更低限速和最大持续时间；通信也失效时只允许有限时预测，随后减速到 T265 定点保持。
- **固定航点与小车真实轨迹不一致。** 路径点必须按小车实际巡迹中心线校准；视觉正常时记录系统性偏差，超过阈值不得继续使用 `PATH_ONLY`。
- **纯速度标定累计误差。** 不以“启动后经过多少秒”作为主要同步量；用小车实时广播的 `track_s_mm` 校正进度，速度只用于状态接收间隔内短时前推。
- **异常速度。** 对 `speed_mm_s` 做绝对上限校验，并在视觉控制器统一限速/加速度/jerk整形。
- **坐标系不一致。** 用 `heading_offset_deg`/`heading_sign` 配置转换；联调日志同时记录原始速度/航向和转换后的 XY。
- **通信线程阻塞飞行。** 串口收发、回调和周期广播均在后台线程；30 ms 飞行循环只读取快照。
- **当前静态伺服地理围栏。** 第一轮小车直线移动距离限制在 0.5 m 内，保持在现有 0.8 m 硬围栏内；完整赛道伴飞另行设计移动围栏/地图边界。
- **回退方案。** 不传 `--enable-car-feedforward` 即完全恢复当前纯视觉行为；蓝牙服务失败时 `--require-car-link` 阻止起飞，否则只能显式选择纯视觉降级。

## 验证方式

### 单元测试

- DCP `CAR_STATE` 编解码与 flags。
- 非 CAR 来源、错误目标、坏 payload、重复/旧 seq 拒绝。
- 速度/航向转换和 ±180° 边界。
- 路径弧长插值、A 点回绕和 `track_s_mm` 跳变拒绝。
- 超龄状态返回不可用，绝不残留旧速度。
- 视觉新鲜 + 车速新鲜时加入前馈。
- 视觉陈旧但路径状态新鲜时进入限速 `PATH_ONLY`。
- 视觉与路径状态都陈旧时只短时预测，随后输出 T265 定点保持。

### 板端台架测试（不带桨）

1. 只运行 `car_link_check.py`，确认 `/dev/bt_serial` 115200 可打开。
2. UAV→CAR：小车连续收到 `UAV_READY/HEARTBEAT`。
3. CAR→UAV：UAV连续收到 10~20 Hz `CAR_STATE`。
4. 静止时速度接近 0；小车沿规定方向低速行驶时，终端显示正确符号的 `(vx, vy)`。
5. 断开蓝牙，确认 0.25 s 内变为 `STALE/LOST`。
6. 重连后重新建立新鲜状态，不复用断开前旧帧。

### 真机验证

1. 第一轮只观察：无人机 1.5 m 悬停，小车 0.05 m/s 沿单一直线移动不超过 0.5 m，记录视觉、路径进度和车速，不接管 XY。
2. 第二轮开启视觉+速度前馈：同一路径、同速度，比较相对误差、追踪延迟和抖动。
3. 第三轮主动遮挡 Tag 0.3~0.5 s，验证切到 `PATH_ONLY` 后仍沿正确方向运动，恢复视觉时无速度跳变。
4. 确认方向正确后提高到 0.10 m/s；无人机总速度仍限 0.15 m/s。
5. 圆弧点重新校准后再做 B→C 分段混合伴飞；完整赛道和远程 `CAR_START` 不纳入首次验证。
