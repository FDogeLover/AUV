## 文档管理子智能体 `doc-manager` 设计方案

### 技能定位

在项目文档体系日益庞大（51 文件、~24K 行、3 层交叉引用）的背景下，提供一个专门管理文档质量的子智能体。

### 操作模式（混合：命令 + 自然语言）

| 命令 | 自然语言触发 | 功能 |
|------|-------------|------|
| `/doc check` | "检查文档一致性"、"验证引用" | 🔍 完整性检查 |
| `/doc map` | "生成文档地图"、"文档结构" | 📋 文档地图生成 |
| `/doc sync` | "更新引用"、"同步文档" | 🔗 引用自动更新 |
| `/doc todo` | "核验 TODO"、"检查待办" | ✅ TODO 一致性验证 |

### 功能详述

#### 1. 🔍 完整性检查（`/doc check`）
- 扫描当前目录下所有 `.md` 文件
- 提取所有 `path/to/file` 形式的引用
- 验证每个被引用路径是否实际存在
- 输出：有哪些断裂引用、指向不存在的文件

#### 2. 📋 文档地图（`/doc map`）
- 扫描当前目录的文档树
- 生成 Markdown 格式的结构总览
- 可选：标注最近修改的文件、文件大小、主题标签

#### 3. 🔗 引用更新（`/doc sync`）
- 当检测到文件重命名或移动时
- 在文件操作完成后，搜索项目中所有引用旧路径的文档
- 自动更新为新的路径

#### 4. ✅ TODO 核验（`/doc todo`）
- 检查 TODO.md 中的 ID 前缀是否唯一（T-001 等）
- 检查 TODO.md 中引用的文件路径是否存在
- 可选：检查 CLAUDE.md 索引中的路径与 TODO.md 的引用是否一致

### 工作范围约束

- **读取**：可以访问项目全局文件，用于理解上下文和验证引用
- **写入**：只修改被调用时的工作目录内的文件
- 在根目录调用 → 可操作 `docs/`、`CyberCamera/` 等全部文档
- 在子目录（如 `docs/architecutre/`）调用 → 只能修改该目录内的文件

### 技能文件结构

```
.agents/skills/doc-manager/
└── SKILL.md         # 完整定义 + 4 个操作模式的详细指令
```

### 关键设计约束

- 不依赖外部 API（纯本地检查）
- 写入前先备份原文件
- 引用更新只修改路径字符串，不改变文档语义内容
- 工作范围以调用时的 CWD 为基准

### 后续完善方向

- 根据使用反馈逐步增加功能
- 可考虑与 session-summary 技能联动（大量文档修改后自动提示生成总结）
