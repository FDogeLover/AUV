问题：2026-07-06 平移测试发现纯X轴指令飞行会带出Y方向9-12cm的规律性漂移，事后核对确认根因是 T265 模块物理安装角度跟机体存在偏差（不是问题2里验证过的"T265与光流坐标系互相一致性"问题，是两者可能一起相对机体偏了同一个角度）。详见项目 CLAUDE.md 已知问题第11条。

**决策（2026-07-07）**：优先尝试物理重新校正 T265 安装角度，而不是在 `t265.py` 里加软件旋转补偿矩阵。

**2026-07-07 已做物理矫正，验证结果矛盾，未能确认有效**：矫正后第一次真机测试，X轴平移Y漂移从基线9-12cm降到6-8cm，坐标交叉相关性也降低，看起来有效；但用户又做了一次角度微调后第二次测试，Y漂移反而变大到12.7cm(持平或超过原始基线)，同时出现降落确认超时、目视可见起降抖动(降落靠人工确认安全)。已排查确认T265物理固定牢固、传感器数据本身健康(手持晃动测试189Hz正常)，问题不在传感器质量。样本量只有2次且结果矛盾，不能下结论矫正是否真的有效，"微调"这一步是变好还是变坏也不确定。详见项目 CLAUDE.md 已知问题第11条最新更新。

同一批还发现并修复了[[已知问题12]]（`land()`降落缺速度门槛），第二次飞行残余速度达-0.12m/s印证了这个问题，已在`navigate()`到达判定里加了速度门槛(`ARRIVAL_VEL_THRESH=0.05`)，`basic/original/basic_radar`三份都改了并同步到板子。

**2026-07-07 第三次复测(问题12速度门槛修复后)：Y漂移回到健康区间**：X轴平移Y漂移6.6-9cm，接近第一次矫正后的6-8cm，比"微调"那次的12.7cm好很多，降落也正常确认"已上锁"。三次数据(矫正#1: 6-8cm已上锁 / 矫正#2微调: 12.7cm超时+抖动 / 问题12修复后: 6.6-9cm已上锁)支持"矫正方向本身有效，微调那次是偶发或副作用"这个判断，但仍是小样本。另外问题12修复过程中还发现并修了第二版bug——`ARRIVAL_VEL_THRESH=0.05`卡在T265瞬时速度噪声量级上，"连续15次达标"的逻辑被噪声尖峰频繁清零导致到达确认永远凑不齐，改成用最近5帧均值(`ARRIVAL_VEL_WINDOW=5`)平滑后解决。

**How to apply**：T265矫正效果目前判断是"大概率有效，但样本量仍不够"，不要说"已确认矫正成功"这种绝对结论。下次涉及T265安装/校准话题，先看CLAUDE.md已知问题11的完整三次记录。如果以后还要调整安装角度，记得：(1) 一次只改一个变量；(2) 多测几次建立样本量；(3) 到达判定的速度检查如果要调参数，别用单帧瞬时值，容易被传感器噪声卡住(参考问题12的第二版修复)。
