# doc-manager — 文档管理子智能体

## 概述

维护 `docs/` 及相关目录中 Markdown 文档的一致性。工作范围以 CWD 为基准：
- **全局读**：可以读取其他目录的文件来验证引用和上下文
- **局部写**：只修改 CWD 及其子目录内的文件

## 操作模式

| 命令 | 功能 | CWD 位置时有效 |
|------|------|---------------|
| `/doc check` | 🔍 完整性检查 | 任意 |
| `/doc map` | 📋 文档地图 | 任意 |
| `/doc sync` | 🔗 引用更新 | 仅限文件移动/重命名后 |
| `/doc todo` | ✅ TODO 核验 | 仅根目录（TODO.md 所在位置） |

### 模式 1 — 🔍 完整性检查（`/doc check`）

**触发词**："检查文档"、"验证引用"、"文档一致性"、"引用断裂"

**流程**：

1. 读取 CWD 及子目录下所有 `.md` 文件（排除 `.git/`）
2. 提取文档中所有形如 `path/to/file`、`dir/file.md`、`subdir/` 的引用路径
   - 使用正则：`(?<!\S)[./\w-]+/[.\w/-]+`（可跨行、含连接符）
   - 排除 URL 链接和代码块中的路径
3. 对每个被引用路径：
   - 从 CWD 或项目根目录构造绝对路径
   - 用 Bash 检查文件/目录是否存在
4. 生成断裂引用报告：
   - 格式：`[断裂] 文件A.md → 引用了「path/to/missing」→ 不存在`
   - 按文档分组展示

**约束**：
- 只检查 `[...](path)` 和内联文本路径，不检查 HTTP URL
- 代码块（```` 包裹区域）内的路径跳过
- 不对猜测性的路径（如只写了文件名没有路径部分）发出警告

### 模式 2 — 📋 文档地图（`/doc map`）

**触发词**："文档地图"、"文档结构"、"目录总览"、"列举文档"

**流程**：

1. 扫描 CWD 及子目录下所有 `.md` 文件
2. 读取每个文件的第一行标题（`# 标题`）
3. 生成层级结构：

```markdown
# 文档结构 — {目录}

```
{dir}/
├── file.md                     ← 标题
├── subdir/
│   └── file.md                 ← 标题
└── ...
```

总览统计：
- 文档数：N
- 总行数：N
- 最近修改：file.md
```

4. 输出给用户

### 模式 3 — 🔗 引用更新（`/doc sync`）

**触发词**："更新引用"、"同步文档"、"移动文件后"、"重命名"

**流程**：

1. 询问用户：旧路径 → 新路径？
2. 搜索 CWD 及子目录下所有 `.md` 文件（含 `.claude/CLAUDE.md`、`.Codex/CLAUDE.md` 等）
3. 查找包含旧路径的行
4. 显示将要修改的文件和改动预览
5. **等待用户确认后再执行修改**
6. 修改后显示修改汇总

**安全约束**：
- 必须显式确认才能执行修改
- 不改动代码块内的路径（除非代码块本身在文档中）
- 在用户确认前打印预览，允许用户中止

### 模式 4 — ✅ TODO 核验（`/doc todo`）

**触发词**："核验 TODO"、"检查待办"、"TODO 一致性"

**流程**：

1. 查找 CWD 下是否有 `TODO.md`（若在子目录调用则仅检查子目录内的 TODO.md）
2. 检查项目：
   - **ID 唯一性**：提取所有 `T-\d{3}` 模式的 ID，检查是否重复
   - **路径存在性**：TODO.md 中出现的引用路径是否真实存在
   - **状态一致性**：（可选）CLAUD.md 索引中的任务状态与 TODO.md 是否有矛盾
3. 输出结果：

```
TODO 核验报告：
  ✅ ID 唯一性：{ok/fail}
  ✅ 路径有效性：{ok/fail}（断裂 {N} 处）
  ⚠️ 状态一致性：{N} 处可能不同步
	```

### 模式 5 — 🔄 根据变更更新文档（`/doc update`）

**触发词**："更新文档"、"根据变更"、"同步文档生态"、"文档更新"

根据当前 git diff 自动维护整个文档生态的一致性。**每次修改前必须展示预览并等待确认。**

**流程**：

1. 执行 `git diff --stat` + `git status --short` 获取变更清单
2. 分类：新增/修改/重命名/删除/新建目录
3. 按变更类型执行对应动作：

| 变更类型 | `doc-manager` 动作 | 示例 |
|---------|-------------------|------|
| **新增文件** | 检查 CLAUDE.md×2 / AGENTS_GUIDE.md 索引是否需要添加引用 | 新增 `vision/servo_controller.py` → 更新 `/vision/` 目录索引 |
| **重命名/移动** | 搜索所有文档，将旧路径引用更新为新路径（引用 `/doc sync`）| `CyberCAM/` → `CyberCamera/` |
| **修改源码** | 检查架构文档/设计文档中对应章节是否需要同步 | 改 `Mission_GPT.py` 状态机 → 更新架构 doc 状态图 |
| **新功能模块** | 提示是否创建架构文档或设计文档 | 新增 `vision/` 模块 → 提示是否补架构说明 |
| **文件删除** | 检查索引中引用，标注或移除 | 删除旧测试文件 → 移除索引 |
| **新建会话总结** | 检查 CLAUDE.md 已知问题速查 + 索引是否需要同步 | 新的总结文件 → 检查 T-xxx 状态是否需要更新 |

4. **安全约束**：
   - 每次修改前展示改动预览（影响哪些文件、改什么）
   - 等待用户确认后再执行
   - `scope=local` 参数可将影响限制在 CWD 内

---

## 通用约束

1. **工作范围**：CWD 是约束基准。不在 CWD 内的文件，只读不写。
2. **询问制**：任何写入操作前，先展示改动预览，等待用户确认。
3. **不碰源码**：只处理 `.md` 文档文件，不改 `.py`/`.c`/`.json` 等代码或配置文件。
4. **不依赖网络**：纯本地文件操作，不调用外部 API。
5. **最小改动**：引用更新只替换路径字符串，不修改文档的语义内容。
