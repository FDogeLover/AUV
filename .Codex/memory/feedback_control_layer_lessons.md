2026-07-23，基于 basic / circle_pole / fire_patrol / warehouse_inventory 四个版本控制调试经验归纳。

## yaw_pid 与 heading_hold 的正确时间线

**开发顺序（常被混淆）：**
```
basic（原始）→ circle_pole（引入 yaw_pid）→ Kp=1.5 触发近90°失控
                                              ↓
                                 事故后设计 heading_hold（安全替代方案）
                                              ↓
                              heading_hold 回填进 basic，成为生产机制
```

heading_hold 是 yaw_pid 事故的直接产物，不是先有 heading_hold 再被 yaw_pid 替换。

**两者的职责层次：**
两者写入同一个通道（se_fc[6]，飞控yaw速率），是同一职责的两代实现，不是同时运行的互补机制。

| | yaw_pid | heading_hold |
|---|---|---|
| 出现版本 | circle_pole | circle_pole 事故后，回填到 basic |
| 输出类型 | 连续 PID 输出 | 离散 ±1/0 dps |
| 最大影响 | 取决于 Kp（无硬性上限） | 1 dps（硬性上限） |
| 安全状态机 | 无 | armed/disarmed/degraded/fault |
| 失控检测 | 无 | 有（仅在饱和时检测） |
| 当前状态 | 默认禁用（喂弧度→≈0输出） | basic 生产使用 |

**heading_hold 每一处保守设计都可追溯到 yaw_pid 的教训：**
- 离散三值输出 → 连续输出+增益失控是事故根因
- runaway 检测只在饱和时触发 → 防"增益偏大→饱和→继续发散"链路
- degraded/fault 双层状态 → 避免一次噪声就锁死整个修正
- armed/disarmed 生命周期 → 明确修正只在飞行期间有效

## Yaw PID 调试的完整教训

- Kp=1.5 触发近90°失控后长期禁用（安全回退：喂弧度→输出≈0）
- 系统性边界测试：Kp=0.3/0.4/0.45收敛，Kp=0.5确认无界发散
- 即便在稳定增益下，与"完全不修正"基线对比，**没有证据证明开启修正有净收益**
- 历史基线（不修正）yaw漂移峰值6.12°自然回归；开启修正后峰值6.13°~10.38°，部分样本更差

**推广结论：不能因为控制器"能收敛"就启用，要证明它比基线更好。对照测试的设计本身是控制调试的一部分。**

## 到达判定的三次演进

**第一版**：严格连续N帧 → T265噪声下达标帧只有30~40%，实际全靠超时跳过

**第二版**：滑动窗口比例制（ratio=0.6） → 单帧噪声不清零进度

**第三版**：补加速度阈值（5帧均值<0.05m/s） → 防止带着残余速度触发降落

**关键耦合bug：** `arrival_timeout_max` 曾等于 `5.0 + arrival_hold_s`，压缩停留时间的同时意外缩短了超时上限。解耦为两个独立常量后问题消失。

**推广结论：超时上限和停留时间是两个独立语义，不应用一个公式耦合。**

## 多信号交叉确认防假阳性

**降落判定**：unlock_sta 单次读值出现假阳性（电机未停但终端显示已上锁），改为连续5帧 + motor_pwm_mask 第二信号交叉验证。

**激光高度**：传感器错误码（0xFFFFFFFF/100≈4.29×10⁷m）只判 >0.05m 无上限时污染高度控制，加 LASER_HEIGHT_MAX_M=10m 上限过滤。

**推广结论：传感器读值用于控制前必须双重校验（合理性下限+上限）；关键状态转换应使用多个独立信号交叉确认，不能单次读值决策。**

## 障碍物避让的滞回设计

避让触发和恢复使用两个独立阈值（POLE_DANGER_DIST_M=0.75m，POLE_RESUME_DIST_M=0.9m），0.15m 滞回区间防止飞机卡在边界反复进出悬停状态。

CIRCLING 阶段整体关闭悬停避让（不只排除当前目标），因为环绕时近距离 yaw 漂移换算的世界坐标误差可能超过容差，排除逻辑容易"认不出"正在绕的目标。

**推广结论：安全触发阈值必须是滞回对（触发+恢复），不能是单值；特定状态下的安全逻辑可以整体关闭，而不是试图通过容差配置绕过。**

## 动作中保持位置闭环

fire_patrol 的 HOVER_DROP（投放）和 RECOVER_HEIGHT（拉高）期间，X/Y PID 全程保持，只允许 Z 轴按 ramp 变化。

如果动作期间关掉位置控制，风场或机构反力导致的漂移会在动作结束后需要大误差修正，在低空场景代价更高。

**推广结论：执行单轴动作（投放、拍照、扫码）期间不应关闭其他轴的位置控制。**

## 控制律量纲一致性

APPROACH_Y_KP=30.0 的误差是方位角（弧度，量级±0.7rad），x_pid/y_pid 的误差是位置（米，量级±0.15m），两者增益相差约40倍是合理的。增益不能跨量纲复用。

**推广结论：写控制需求时，每个 PID 的误差量纲必须显式声明；向 AI 提需求时增益初值要注明对应的误差量纲和量级。**

## 传感器可信区间决定控制切换点

basic 起飞分两阶段：35cm 以下盲飞（T265近地面定位质量差），35cm 以上才接入 PID 闭环爬升。35cm 不是随意选的，而是真机测试发现15cm 时 T265 精度下降触发起飞超时。

**推广结论：控制切换点（开环→闭环）必须基于传感器在各高度/状态下的实际可信度，不能从零高度就立即接管。**

## 单次触发动作的状态保护

fire_patrol 用 `fire_triggered=True` 保证全程只响应一次火情；warehouse_inventory 用 InventoryStateMachine 的强制转移校验（非法转移直接抛异常）保证同样的约束。

**推广结论：对于"触发一次后不可重复"的动作，必须在状态层面封锁重入路径，不能靠调用方判断逻辑保证。**
