2026-07-23 明确：大部分代码由AI实现，复盘目的是理解代码以便未来清晰地向AI表达需求。

## 复盘的正确姿势

逐行理解所有代码是低效的。应聚焦三类信息：

**1. 工程决策（Why）**
为什么这样设计，而不是另一种显而易见的方式。
这是AI在没有充分上下文时最容易做错的部分，也是最值得记录的部分。
例：起飞为何分两阶段？到达判定为何用比例制而非严格连续帧？

**2. 调试关键点（Debug）**
出问题时先看哪里，哪些字段是诊断入口，有哪些已知的假阳性/假阴性场景。
例：`fault_reason` vs `degraded_reason`，降落确认的`motor_pwm_mask`二次验证。

**3. 架构特点（How）**
模块的职责边界、接口设计、与其他模块的耦合关系。
例：状态机单线程 + 通信层多线程的分层，`se_fc`是共享内存而非消息队列。

## 不需要深入的部分

- 标准库/工具类的用法（logging、threading、psutil等）
- 格式化输出、日志字段命名
- 参数默认值（看注释即可）

## 复盘后的输出

复盘结束应能回答：
- 如果X出问题，我先看哪里？
- 如果要改Y功能，我需要告诉AI哪些约束？
- 这个模块的接口是什么，调用方需要知道什么？
