`drone_control/basic/` 是所有扩展版本的基础，2026-07-23 完成完整框架复盘。

## 整体架构

```
main.py（入口）
 └─ 等待一键按钮 → T265初始化 → 串口 → Mission → 状态机后台线程
         ↓
Mission_GPT.py（30ms主循环）
 IDLE → TAKEOFF → NAVIGATE → LAND → END
         ↓                    ↑ 写se_fc（加锁）
Lprotocol.py 三线程通信层（监听/T265发送/指令发送）
```

状态机单线程串行，通信层多线程并行，两者只通过 `re_fc`/`se_fc` 共享内存交互。

## 关键工程决策

**起飞分两阶段（35cm盲飞+PID闭环爬升）**
近地面T265/激光精度差，先盲飞离开恶劣区域，再闭环爬升到目标高度。不能一步到位。

**高度用激光直接覆盖T265 Z轴**
T265的Z轴有视觉漂移，激光测距精度更高。不是融合而是直接替换，简单有效。
过滤条件：`0.05m < laser_h <= 10m`，上限防止传感器错误码（0xFFFFFFFF/100）污染数据。

**到达判定：滑动窗口比例制（非严格连续帧）**
实测T265噪声下达标帧只有30~40%，严格连续N帧几乎不可能凑够，航点全靠超时跳过。
改为：最近15帧中≥60%帧同时满足位置+速度阈值→确认到达。速度取5帧均值防噪声尖峰。

**降落期间串口不能关**
飞控物理降落依赖持续收到T265速度参考帧（AA01）。串口关闭=速度参考断流=飞机漂移。
降落确认用`unlock_sta + motor_pwm_mask`双重验证，连续5帧才认为真正上锁。

**stop_all()里上锁指令必须最先写**
`se_fc[7]=101` 在任何资源释放操作之前写入，因为发送线程独立运行，越早写越早让飞控收到上锁指令。

## 调试关键点

- 飞控串口超时2s→急停：不一定是线断了，可能是飞控卡死或write_timeout触发
- `fault_reason`非None→控制器永久锁死，需重启任务；`degraded_reason`→临时降级，条件改善自动恢复
- 航点被超时跳过：看日志`arrival_distance_m`和速度字段，确认是位置超限还是速度超限
- 降落确认假阳性：看`motor_pwm_mask`字段，`unlock_sta=0`但`motor_pwm_mask≠0`是已知问题

## 传感器分工

| 传感器 | 负责 | 精度特点 |
|--------|------|---------|
| T265 | XY水平位置 + Yaw | 累积漂移，近地面质量差 |
| 激光测高 | Z轴高度 | 精度高，偶发错误码需过滤 |
| 飞控IMU | 姿态角（roll/pitch）+ 角速度内环 | 高频稳定 |
